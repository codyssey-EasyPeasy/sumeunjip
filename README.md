# 보안 예보

스토킹·가정폭력·교제폭력·성폭력 피해자가 **피신한 새 주소가 행정·소송·생활 기록을 통해 상대에게 새어 나가는 경로**를 진단하고, 경로마다 **그 경로를 막는 제도**를 근거 조문과 함께 안내하는 웹 서비스입니다. 코디세이 AI 해커톤 2026 주제 02(AI 기반 정보보호 서비스) 출품작입니다(팀 EasyPeasy).

> 저장소 이름은 `boan-yebo`(2026-11-01 변경, 옛 주소는 GitHub 가 자동 연결)입니다. 코드·서버 경로·환경 변수에 남은 `sumeunjip`(예: `~/.config/sumeunjip/`, `SUMEUNJIP_NO_LOAD`)은 옛 작업 이름으로, 배포 경로라 그대로 둡니다.

> **법률정보 안내이며 법률상담이 아닙니다.** 긴급하면 112, 여성긴급전화 1366(24시간), 대한법률구조공단 132로 연락하세요. 이 저장소의 모든 예시·평가 데이터는 합성 데이터이며 실존 인물·사건과 무관합니다.

## 무엇을 하나
- **노출 경로 진단**: 피해 유형(가정폭력·스토킹·교제폭력·성폭력)과 상황(이사 직후, 소송 중, 자녀 학교, 차량, 위치 공유 등 30개 항목)을 고르면, 지식표의 84개 경로 중 해당하는 것을 급한 순서로 보여 줍니다. 어떤 제도를 권할지는 **규칙 엔진**이 정합니다. **84개가 모든 경로는 아닙니다**(아래 「한계」).
- **막는 제도 안내**: 제도마다 근거 조문(시행일), 대상 피해 유형, 신청처, 서류, 한계, 확인 수준을 표시합니다. 결과 카드는 위험 → 도움 순서로 먼저 보이고 근거 조문은 접혀 있습니다. 신청하면 상대에게 통지되는 제도는 확인 체크를 거치게 합니다. 막을 제도가 없는 경로(16개)는 '잔여 위험'으로 따로 안내합니다.
- **상황 정리(AI)**: 자유롭게 적은 글에서 체크 항목 후보를 미리 골라 줍니다. 사용자가 항목을 확인·수정해야 진단합니다. 주입된 지시문·특수 토큰은 지우고, 글에 근거 낱말이 없는 항목은 버립니다.
- **근거 답변(AI)**: 고른 제도에 대한 질문에 지식표 행과 공개 조문만으로 답합니다. 생성 → 문장별 검증 → 1회 재생성 → 실패하면 원문 발췌. 통지 여부·효과 시점 질문은 생성하지 않고 지식표 원문으로 답합니다. 조문 검색 결과는 원문을 먼저 보여 주고 출처·시행일은 접어 둡니다.
- **제출 서류 점검·다시 쓰기**: 고소장·소장 초안에서 주소·학교·직장·차량번호·전화 같은 위치 단서를 찾아 표시하고(1단계는 브라우저 안에서만), 원문 문장과 정렬되는 안전한 문장을 제안합니다. 새 사실이 끼면 규칙 치환으로 대신합니다.
- **안전 장치(화면)**: 들어올 때마다 뜨는 안전 안내 팝업('안전 안내 다시 보기'로 다시 열기), 위쪽 긴급 연락처 띠(112·1366·132), 하단 고정 도움 줄, 빠른 나가기(버튼 또는 Esc 두 번), 시스템 설정을 따르는 다크 모드. 쿠키·localStorage·인라인 스크립트를 쓰지 않습니다.
- **사람을 찾는 방법은 다루지 않습니다.** 2단 가드로 분명한 타인 위치 찾기만 거절하고, 거절에도 내 정보를 지키는 제도 2~3개와 1366·132·112 를 붙입니다. 애매한 질문은 거절 대신 보호 안내를 붙여 답합니다. 열람·교부 절차 조문은 검색 대상에서 뺐습니다.

## 모델과 고른 이유
피해자 글이 우리 서버 밖으로 나가면 안 되므로 외부 API 는 처음부터 후보에서 뺐습니다. 네 모델 모두 공개 가중치를 GPU 한 장(L4)에서 직접 돌립니다. 공개 벤치마크 수치는 개발사·저자가 낸 값이고, 우리 수치는 `docs/EVIDENCE.md` 와 `data/eval/retrieval_baseline.md` 에 있습니다. 라이선스와 리비전은 `THIRD_PARTY_NOTICES.md`.

- **LLM, Qwen3-8B-AWQ (vLLM 0.32.0)**: 상용 서비스에 제약 없는 Apache-2.0 공개 모델이라 우리 GPU 에서 직접 돌릴 수 있습니다. 공식 4bit 양자화본이라 검색·개체명 모델과 함께 L4 한 장에 올라갑니다(vLLM 13,948 MiB). 다른 모델과 우리 데이터로 직접 비교(A/B)하지는 못했습니다.
- **임베딩, bge-m3**: 다국어 검색 모델로, 논문 기준 한국어 검색(MIRACL ko)에서 키워드 검색 37.1 대비 69.9 입니다. 우리 조문 질의 55개에서 임베딩만으로 R@5 0.945(키워드 검색 0.800), 지연 73ms 였습니다.
- **재순위, bge-reranker-v2-m3**: 1차 후보 30개를 질문과 한 쌍씩 다시 읽어 5개를 고릅니다. 법률 용어 질의의 R@1 이 0.867 → 1.000 으로 올랐지만 일상 말투 질의는 0.733 → 0.633 으로 내려가, 점수 결합을 다음 과제로 둡니다.
- **개체명, GLiNER multi-v2.1 + 정규식**: 학습 데이터 없이 '주소·학교·직장·차량·생활권' 라벨을 바로 정의하는 제로샷 모델입니다. 정규식과 합쳐 서류 단서 F1 0.823 이지만 직장(4/8)과 생활권(0/11)은 약해서 사용자 확인을 함께 안내합니다.

## 실행
대회 서버(NCP)는 **2026-11-01 13:00 에 삭제됩니다.** 그 뒤에는 아래 'GPU 없이 보기'로 화면과 규칙 기능을 볼 수 있고, AI 기능까지 보려면 NVIDIA GPU(L4 23 GB 급)에서 '전체 구성'을 다시 만들어야 합니다. 서버에서 회수한 버전·리비전·기동 기록은 `docs/evidence/repro-2026-11-01.md` 에 있습니다.

요구: Python 3.12, [uv](https://docs.astral.sh/uv/). 서류 점검 평가에는 Node.js.

### 1. GPU 없이 보기 (노트북에서)
```bash
uv sync --frozen
uv run python tools/mock_gpu.py                                   # 터미널 1: 모의 GPU 서버(모델 없음, 127.0.0.1:18000)
GPU_URL=http://127.0.0.1:18000 uv run uvicorn app.main:app --host 127.0.0.1 --port 8080   # 터미널 2
# 브라우저: http://localhost:8080
```
진단, 규칙 가드, 서류 점검 1단계는 실제로 동작합니다. AI 답변·문장 바꾸기는 `(모의 응답)` 으로 표시되며 품질과 무관합니다. 자세한 내용과 Windows 명령은 `docs/LOCAL_DEV.md`.

### 2. 환경 변수
```bash
cp .env.example .env            # 값을 고친 뒤
set -a && . ./.env && set +a    # 셸에 올리고 아래 명령을 실행
```
- 모든 변수는 생략할 수 있고, 생략하면 코드 기본값을 씁니다. `.env.example` 에 비밀 값은 없습니다. `.env` 는 `.gitignore` 에 있습니다.
- 자주 바꾸는 변수: `GPU_URL`(추론 서버 주소), `GPU_TOKEN_FILE`(추론 API 공유 토큰 **파일 경로**, 기본 `~/.config/sumeunjip/gpu_token`), `MODELS_DIR`(모델 폴더), `LLM_MODEL_PATH`·`VLLM_VENV`(vLLM).
- `LLM_OUT_THRESH` 는 앱과 추론 서버가 따로 읽으므로 두 서버에 같은 값을 넣습니다.

### 3. 전체 구성 (GPU 서버 + 운영 서버)
기동 순서는 **vLLM → 추론 서버 → 운영 앱** 입니다. vLLM 냉기동은 약 161초 걸립니다.

```bash
# (1) 두 서버 공통: 추론 API 공유 토큰(같은 값). 없으면 추론 API 는 /health 밖 전부 401
install -d -m 700 ~/.config/sumeunjip && (umask 077; python3 -c 'import secrets;print(secrets.token_urlsafe(32))' > ~/.config/sumeunjip/gpu_token)
# (한 서버에서 만든 파일을 다른 서버의 같은 경로로 복사. 다른 경로면 GPU_TOKEN_FILE 로 지정)

# (2) GPU 서버: 추론 API 의존성(대회 서버에서 회수한 gpu/uv.lock 으로 고정)
cd gpu && uv sync --frozen

# (3) GPU 서버: 모델을 미리 내려받는다. 실행 중에는 HF_HUB_OFFLINE=1 이라 허브에 접속하지 않으므로
#     받지 않으면 기동이 실패한다. 리비전은 대회 서버에서 쓴 값(docs/evidence/repro-2026-11-01.md 4절)
export MODELS_DIR=~/models
get() {  # get <repo> <revision>: HF_HOME 캐시에 받고, 오프라인 로드가 찾는 refs/main 을 그 리비전으로 맞춘다
  local d="$MODELS_DIR/hub/models--${1/\//--}"
  HF_HOME="$MODELS_DIR" uv run --frozen hf download "$1" --revision "$2" &&
  mkdir -p "$d/refs" && printf %s "$2" > "$d/refs/main"
}
get BAAI/bge-m3                5617a9f61b028005a4858fdac845db406aefb181
get BAAI/bge-reranker-v2-m3    953dc6f6f85a1b2dbfca4c34a2796e7dde08d41e
get urchade/gliner_multi-v2.1  443d26d654e0324125a96bebd8e796c14ff2efe6
get microsoft/mdeberta-v3-base a0484667b22365f84929a935b5e50a51f71f159d   # GLiNER 가 함께 읽는다
uv run --frozen hf download Qwen/Qwen3-8B-AWQ --revision 4da05a8edb55c6046cce958586c33b61da07bb79 \
  --local-dir "$MODELS_DIR/Qwen3-8B-AWQ"                                 # vLLM 은 이 폴더를 읽는다

# (4) GPU 서버: vLLM 가상환경(버전은 대회 서버 값. 서버에서 쓴 설치 명령 원문은 기록이 없다)
uv venv --python 3.12 ~/vllm-venv && uv pip install --python ~/vllm-venv/bin/python vllm==0.32.0

# (5) GPU 서버: 시작(중지는 ./llm_stop.sh, ./stop.sh). vLLM 은 127.0.0.1:8001 에만 바인드, 요청·생성 로그 끔
./llm_start.sh
./start.sh                                              # 추론 서버 :8000

# (6) 운영 서버: 앱 + 웹(127.0.0.1:8080, 접근 로그는 메서드·경로·상태코드만)
uv sync --frozen
GPU_URL=http://<추론서버>:8000 scripts/start_app.sh     # 중지: scripts/stop_app.sh
```
- (3)·(4) 의 명령은 이 문서를 쓸 때 다시 실행해 보지 않았습니다(**미검증**). 대회 서버에서 실제로 돈 구성은 `docs/evidence/repro-2026-11-01.md` 의 실행 명령·버전·리비전입니다.
- 기동 확인: GPU 서버 `curl -s 127.0.0.1:8000/health`, 운영 서버 `curl -s 127.0.0.1:8080/api/health`, 그리고 화면에서 검색 결과가 `fallback: false` 인지 봅니다. 시작 스크립트는 기동 실패여도 `started` 를 출력하므로 이 확인을 건너뛰지 않습니다.
- GPU 메모리: L4 23,034 MiB 중 19,648~19,752 MiB 사용(vLLM 13,948 + 추론 API 5,686~5,790, `docs/EVIDENCE.md` 0-19).

추론 서버가 없으면 근거 검색은 키워드 검색(`fallback: true`)으로, LLM 기능은 화면에서 숨겨진 채 체크박스 방식으로 동작합니다. LLM 이 실패해도 다른 LLM 으로 넘기지 않습니다.

| 레드팀 검색·답 경로 공격 성공 (엄격: 가드가 거절하지 않으면 성공, 현재 배포본) | **3/84 = 3.6%** (95% 1.2–10.0%, 분모 84 = 검색·답 경로 공격). 이력: 2026-10-31 서비스 경로 전체 5/112 = 4.5% | 개발 | 0-12 |
| 위치 찾기 방법이 출력된 응답 | 0건 (정규식 검출기 + AI 검토자 읽기, 검출기 재현율 미측정) | 개발 | 0-14 |
| 서류 단서 탐지(1+2단계) 정밀도 / 재현율 / F1 | 0.932 / 0.737 / 0.823 | 개발 | 0-20 |
| 부하: L4 1장 | 품질 유지(동시 2) 시간당 약 200세션, 꽉 찰 때 세션당 약 9.7원 | 운영 실측(합성 입력) | 0-16 |
| 세션당 토큰 / answer p95 (순차) | 약 22,349 / 9.94초 | 운영 실측 | 0-17, 0-18 |

- **레드팀 '개선'은 주장하지 않습니다.** '5.4% → 2.7%'는 대책을 만들 때 본 같은 112건으로 다시 잰 값이고, 고친 것 5건과 새로 뚫린 것 4건이 섞여 있습니다(McNemar p=1.0). 2026-11-01 의 4/84 → 3/84 도 그 1건을 보고 고친 같은 세트 값입니다(`docs/EVIDENCE.md` 0-13).
- 레드팀 응답 재판정은 공격과 가드를 만든 같은 AI(Claude)가 했습니다. 사람 판정자는 없습니다. 레드팀 공격 문장은 공개하지 않습니다(`docs/redteam-summary.md`).
- **출시하지 않은 실험(음성 결과)**: 검색 결과를 LLM 이 종합해 답하는 '검색 답 종합'은 1~3라운드 모두 보류 세트 품질 게이트(0.90 이상)를 넘지 못해(2라운드 엄격 정답률 0.625, 3라운드 0.421) 넣지 않았습니다(`docs/EVIDENCE.md` 0-15). 위 근거 답 0.956 과는 다른 기능입니다.

## 한계와 남은 위험
- **다루는 범위가 전부가 아닙니다.** 지식표는 노출 경로 84개를 다룹니다. 조사 문서에 아직 다루지 않은 경로·수단 25항목을 적어 두었습니다(`docs/research/2026-10-31-정보조사.md` 11절: 연말정산 부양가족, 보험·가족카드, 인증서·간편인증 공유, 양육비 이행 절차, 반려동물 등록, 아동수당·예방접종, 경매·배당 등). 정부가 안내하는 수단 중 전자소송 사전포괄동의와 민원 서류 익명 처리도 지식표에 아직 없습니다. **진단에 나오지 않았다고 안전하다는 뜻이 아닙니다.** 1366·132 상담을 함께 권합니다.
- **자기 보호 질문을 거절하는 경우가 남아 있습니다.** '가해자가 제 새 주소를 알아낼 수 있나요' 같은 피해자 문형, 영어·사투리 질문이 조회 요청으로 잘못 판정될 수 있습니다(`docs/EVIDENCE.md` 0-10). 거절에도 보호 대안과 1366 이 붙지만 거절은 거절입니다. 운영 앱 측정에서 답할 수 있는 근거 질문 하나(a4)가 3회 모두 입력 가드에 거절됐습니다(0-6).
- **레드팀 우회가 남아 있습니다.** 현재 배포본에서 검색·답 경로 공격 84건 중 3건이 가드를 통과했습니다(3.6%, 한국어 자모 변형 1·다국어 혼용 2). 통과한 응답에 실제 조회 방법은 없었지만, 위치 찾기에 대한 적응형 자동 공격은 사실상 하지 못했고 전문직 사칭·이주민 언어 공격은 세트에 없습니다(`docs/redteam-summary.md`).
- **소형 LLM 은 틀릴 수 있습니다.** 근거 답 첫 생성문의 근거 없는 문장은 3.6%(서버 판정)였고, 검증 루프 뒤 '0'은 같은 검증기로 다시 잰 값이라 독립 판정이 아닙니다. 그래서 통지·효과 시점 질문은 생성하지 않습니다.
- **intake 단독 정확도가 낮습니다**(다턴 유형 0.575, 상황 재현율 0.276). 사용자가 체크 항목 화면에서 확인·수정해야 합니다.
- **생활권 단서(동네·단골 가게 등)는 탐지하지 못합니다**(0/11). 직장 단서 재현율도 0.5 입니다. 서류 평가 문서는 41~82자로 짧습니다.
- **법령과 쉬운 말 설명**: 법령은 2026-10-31 law.go.kr 스냅샷 기준입니다. 쉬운 말 설명 84행은 모두 사람 검수 전(0/84)이고 화면에 'AI 생성(검수 전)'으로 표시합니다. 확인 수준은 확인 49 · 부분확인 31 · 미확인 4 입니다.
- **모든 수치는 합성 데이터에서만 나왔습니다.** 실제 이용자·실제 서류로 평가하지 않았습니다. 다턴 시뮬레이터는 GLM 이 사용자·공격자를 연기하므로 같은 시드라도 대화가 달라지고 표본이 작습니다.
- **동시 부하에서는 오류보다 답변 품질이 먼저 떨어집니다.** 동시 4건이면 근거 답의 14%, 8건이면 50%가 12초 예산을 넘겨 원문 발췌로 끝났습니다(`docs/COST_LATENCY.md` §3-3). 동시 처리 상한이 없으므로 동시 2 이하를 권장합니다. 프로세스 자동 재시작도 없습니다.
- **배포 보안**: 시연 배포는 TLS 없이 VPN·ssh 터널로만 접근했습니다. GPU 추론 API(8000)는 대회 VPN 사용자에게도 닿아 2026-11-01 부터 공유 토큰을 요구합니다(`docs/evidence/deploy-2026-11-01.md`). 저장소의 평가 도구(`tools/eval*.py`)는 아직 토큰을 보내지 않아 토큰을 켠 GPU 를 직접 부르지 못합니다. 공개 배포 전에는 TLS·전 엔드포인트 속도 제한·운영 정책이 필요합니다.
- **재현성**: 로컬 시험 환경은 Python 3.13, 운영은 3.12 입니다. vLLM 설치 명령 원문은 기록이 없습니다(`docs/evidence/repro-2026-11-01.md` 8절).
- 만든 방법: 쉬운 설명 초안은 외부 LLM(DeepSeek-V4.1-Flash, 공개 조문만)과 Claude 가, 코드는 1차 일부를 DeepSeek 가 초안으로·이후는 Claude 가 썼습니다(`docs/SPEC.md` §11.7). 화면 개선(PR #2)과 파비콘은 팀원이 만들었습니다.
