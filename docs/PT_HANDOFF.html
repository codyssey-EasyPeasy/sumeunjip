1. 한 줄 소개 · 핵심 메시지 3개 · 주제 02 적합성

1.1 한 줄 소개

"스토킹·가정폭력 피해자의 새 주소가 새는 경로를 진단하고 막는 제도를 근거와 함께 안내하는 피해자 본인용 AI 자가 점검 도구" (pt/index.html 1쪽 부제. README.md 3행도 같은 뜻)

마무리 문장(16쪽): "피신한 곳은, 피신한 곳으로 남아야 합니다."

1.2 핵심 메시지 3개

#메시지뒷받침 (출처)
①주소는 서류를 타고 샙니다. 막는 제도는 있지만 흩어져 있고, 신청해야만 작동합니다.주소가 드러날 수 있는 경로 84개, 그중 16개는 막을 제도가 없음 (data/knowledge.json). 소송 단계 주소 비공개는 신청주의, 일부 제한은 신청 사실이 상대에게 통지됨 (research/2026-10-31-정보조사.md, pt/index.html 3쪽)
②결정은 규칙이, AI 는 돕기만 합니다. 그리고 AI 가 확인하지 못한 문장은 내보내지 않습니다.어떤 제도를 권할지는 규칙 엔진(app/engine.py)만 정함. AI 가 고른 항목은 본인이 확인해야 제출. 답은 문장마다 근거를 확인하고, 확인 안 되면 원문 발췌로 대신함 (gpu/verify.py)
③입력은 저장하지 않고 밖으로 보내지 않으며, 추적 도구가 되지 않게 설계했습니다.DB 없음, 외부 LLM 호출 0, 표지 문자열 60회 전송 뒤 세 로그 0건 (docs/evidence/infra.md §6). 다른 사람 찾기 질문 35/35 거절·정상 질문 오거절 0/25 (data/eval/results_app_llm.json, 합성 데이터 기준)

1.3 주제 02(AI 기반 정보보호 서비스)에 맞는 이유

  • 지키는 정보가 '피해자의 주소'라는 가장 민감한 개인정보입니다. 서비스 목적 자체가 주소 노출을 막는 정보보호입니다. (README.md 3행)
  • AI 를 보호 쪽에만 씁니다. 조문 검색(임베딩·재순위), 서류 속 위치 단서 찾기(개체명 인식), 말로 적은 상황 정리·근거 답·안전한 문장 제안(내부 LLM). (gpu/server.py)
  • 서비스 자체도 정보보호 설계입니다. 저장 0 · 외부 전송 0 · AI 모델을 직접 띄운 GPU 서버 안에서만 실행 · 로그엔 '메서드 경로 상태코드'만. (docs/architecture.md, docs/evidence/infra.md §6)
  • AI 의 위험(이중 용도·프롬프트 주입·지어낸 답)을 직접 막고 숫자로 점검했습니다. 2단 가드, 출력 가드, 답 검증 루프, 자체 레드팀 121개. (docs/redteam-summary.md)

2. 서비스 한눈에 보기

구분내용
문제피해자가 피신해도 새 주소가 행정·소송·생활 기록(주민등록, 소장 송달, 자녀 학교, 차량, 우편 등)을 타고 가해자에게 새어 나갈 수 있습니다. 막는 제도는 흩어져 있고 신청해야만 작동하며, 어떤 제도는 신청 사실이 상대에게 통지됩니다. (README.md, research/2026-10-31-정보조사.md)

하지 않는 것사람을 찾는 방법은 다루지 않습니다. 다른 사람의 주소·위치를 찾으려는 질문은 거절하고 보호 제도를 대신 안내합니다. 법률정보 안내이며 법률상담이 아닙니다.

4.1 서버 배치

출처: docs/architecture.md 배치도, docs/evidence/infra.md §1·§3

  • 저장소 문서의 서버 이름은 hk-ops(운영)·hk-gpu(추론)입니다. 대회 서버 이름은 각각 inno-server-028·inno-gpu-028 입니다(docs/evidence/infra.md §1 표). CPU 모델명·OS 버전은 저장소에 기록이 없어 미확인입니다(운영 측 정보). PT 에는 '운영 서버'·'GPU 서버' 라는 역할 이름을 쓰는 것을 권합니다.

4.3 밖으로 나가지 않는 것

  • 사용자 입력을 외부 LLM·외부 API 로 보내는 경로가 없습니다. 런타임 LLM 은 GPU 서버의 Qwen 하나뿐이고, 실패해도 다른 LLM 으로 넘기지 않습니다(화면은 체크박스 방식으로 계속). (docs/SPEC.md §11.7)
  • 런타임 코드의 외부 주소는 '빠른 나가기' 이동 대상(구글 '날씨' 검색) 하나뿐입니다. (docs/evidence/infra.md, web/static/app.js)
  • GPU 서버가 기동할 때 모델 허브(HF Hub)에 보내던 파일 확인 요청(사용자 데이터 없음)은 커밋 6672867 에서 HF_HUB_OFFLINE=1 로 껐습니다(gpu/start.sh 7행, gpu/llm_start.sh 28행). 다시 띄운 뒤 0회인지 잰 기록은 미확인입니다.

  5. 화면: '지금 먼저 할 일'(급한 제도 최대 5건 + 급한 잔여 위험) + 나머지는 접어 둠

출처: app/engine.py, web/static/app.js (TOP_MAX=5)

6.2 근거 질문 ("이게 무슨 뜻인가요?")

  1. 질문 → 운영 API 1차 가드
  2. 통지 여부·효과 시점 질문이면 AI 가 만들지 않고 지식표 원문을 그대로 보여 줌
  3. 추론 서버 2차 가드 → 지식표 행 + 공개 조문만으로 Qwen 이 답 생성
  4. 검증: 규칙 → 재순위 모델(문장마다 근거 대조) → Qwen 검증기
  5. 실패하면 한 번 다시 생성 → 그래도 실패하거나 시간이 4초 미만 남으면 원문 발췌 (전체 12초)
  6. 출력 가드 → 화면(답 종류 배지와 함께)

출처: gpu/verify.py, gpu/server.py, app/llm.py

6.3 서류 점검

  1. 기본 점검: 브라우저 안 규칙만. 서버로 보내지 않음
  2. 정밀 점검: 사용자가 눌렀을 때만 서버로 → GLiNER + 정규식 → 단서 위치만 돌려줌
  3. 안전한 문장으로 바꾸기: Qwen 제안 → 원문과 맞는지·없던 숫자·이름·장소가 생겼는지 검사 → 문제 있으면 규칙 치환(예: [주소 비공개])

출처: web/static/detect.js, app/main.py, gpu/server.py

  2. 규칙 + 임베딩 의도 점수로 판정
  3. 등급 5개:

  • 일반 → 그대로 진행
  • 애매함 → 진행하되 보호 안내 상자를 붙임
  • 제3자 탐색 → 거절 + 보호 제도 대안 2~3개 + 1366·132·112
  • 다시 써 주세요 → 초성만 쓴 글
  1. 대화 이력(최근 6턴)도 이어 붙여 다시 판정. 같은 가드를 운영 API·추론 서버에서 두 번

13. 예상 질문과 답변 10개

Q1. 왜 LLM 이 제도를 고르지 않나요? AI 서비스라면서요.

A. 틀린 안내가 생명과 직결되기 때문입니다. 어떤 제도를 권할지는 규칙 엔진이 지식표 84행을 조건대로 평가해 정하고, 같은 입력엔 늘 같은 답이 나옵니다. AI 는 근거 검색·재순위, 말로 적은 상황의 정리 제안, 서류 단서 찾기, 문장 제안에만 씁니다. AI 가 고른 항목도 본인이 확인해야 반영됩니다. (app/engine.py, pt/index.html 8쪽)

Q2. 개인정보는 어떻게 다루나요?

A. 회원가입이 없고 DB 도 없습니다. 대화 이력은 브라우저 메모리에만 있다가 요청할 때 같이 보내고, 새로 고침이나 빠른 나가기로 사라집니다. 서버 로그엔 '메서드 경로 상태코드'만 남고, 특수 표지 문자열을 60번 보낸 뒤 세 로그를 검색해 0건임을 확인했습니다. 서류 기본 점검은 브라우저 밖으로 나가지 않습니다. (docs/architecture.md, docs/evidence/infra.md §6)

Q3. 가해자가 이 서비스를 쓰면요?

A. 이 서비스는 막는 방법만 안내하고 사람을 찾는 방법은 다루지 않습니다. 열람·교부 절차처럼 찾기에 쓰일 수 있는 조문은 검색 대상에서 뺐고, 다른 사람의 위치를 찾는 질문은 운영 서버와 GPU 서버에서 두 번 판정해 거절합니다. 자체 공격 121개로 점검해 서비스 전체 공격 성공률을 5.4% → 2.7% 로 낮췄고, 실제 조회 방법을 낸 경우는 0건이었습니다(자체 점검 기준). 막을 제도가 없는 경로도 "주소가 남을 수 있다"는 사전 안내만 합니다. (docs/redteam-summary.md, data/laws/articles.jsonl exposable)

Q4. 변호사법 위반 아닌가요?

A. 변호사법 제109조는 대가를 받는 비변호사 법률사무를 금지합니다. 우리는 무료·비영리이고, 공식 조문과 기관 안내만 보여 주며, 신청서를 대신 쓰지 않습니다. 화면마다 "법률정보 안내이며 법률상담이 아닙니다"를 알리고 132 로 연결합니다. 다만 AI 법률정보 서비스에 대한 유권해석은 없어(미확인) 실제 운영 전에는 법률 검토가 필요합니다. (pt/index.html 13쪽)

Q5. 정확도는 어느 정도인가요? 실제로 검증했나요?

A. 합성 데이터 기준으로 진단 56/56, 서류 단서 F1 0.823, 근거 답 정답률 0.956 입니다. 실제 피해자·실제 서류로는 평가하지 않았고, 이 점을 한계로 명시했습니다. 약점도 공개했습니다: 생활권 단서 0/11, 직장 단서 4/8. 다음 단계가 1366·지원기관과의 현장 검증입니다. (data/eval/results.json, results_llm.json, README.md 한계)

Q6. 8B 소형 모델이면 틀리지 않나요?

A. 틀릴 수 있습니다. 그래서 세 겹으로 막습니다. ① 상대에게 알려지는지·언제 효력이 나는지 같은 질문은 AI 가 만들지 않고 지식표 원문을 보여 줍니다. ② 답은 문장마다 근거를 확인하고, 실패하면 한 번 다시 만들고, 그래도 안 되면 원문 발췌로 대신합니다. ③ 'AI 생성' 배지를 붙입니다. 첫 생성에서 근거 없는 문장이 3.6% 있었고 최종 출력에서는 0% 였습니다(같은 검증기로 다시 잰 값, 독립 판정 아님). 말로 설명하기 단독 정확도는 낮아서(다턴 시뮬레이션 유형 0.575) 본인 확인 단계를 둡니다. (gpu/verify.py, data/eval/results_llm.json, sim_results/v3-20261031)

Q7. GLM 이나 외부 LLM(ChatGPT 등)을 쓰나요?

A. 서비스 중에는 쓰지 않습니다. 런타임 LLM 은 GPU 서버에 직접 띄운 Qwen3-8B 하나뿐이고, 실패해도 다른 LLM 으로 넘기지 않습니다. 앱·GPU 코드에 GLM 주소는 0건입니다. GLM-5.3-Flash 는 개발 기기에서 합성 사용자·공격자 시뮬레이터, 레드팀, 합성 시연 데이터 만들기에만 썼습니다. 쉬운 설명 초안은 빌드 때 공개 조문만으로 외부 LLM 을 써서 만들었고(어떤 모델인지는 저장소 기록 없음, 미확인) 화면에 'AI 생성(검수 전)'으로 표시합니다. (docs/SPEC.md §11.7, pt/index.html 6·11쪽)

Q8. 앞으로 어떻게 확장하나요?

A. 저장소에 적힌 계획은 네 가지입니다. 1366·지원기관과 공동 시범으로 현장 검증, 법 개정 추적(2027.4.22. 스토킹 피해자보호명령 시행 반영), 4대보험·연말정산·공탁·양육비 등 빈 경로 25건 추가 조사, 막을 제도가 없는 16개 경로를 정책 제안 자료로 정리. 공개 배포 전에는 TLS, 모든 기능의 속도 제한, 쉬운 설명 사람 검수가 필요합니다. (pt/index.html 15쪽, docs/architecture.md, README.md)

Q9. 기존 서비스와 무엇이 다른가요?

A. 미국 Safe at Home·영국 익명 선거인 등록처럼 해외엔 대체 주소 제도 자체가 있지만 한국엔 없어서, 흩어진 제도의 체크리스트가 필요합니다. 법무부 가해자 위치 알림(2026.6~)은 가해자 접근을 알리는 것이고, 우리는 기록·서류 경로를 막습니다. NNEDV·myPlan 같은 안전계획 도구는 일반 안내이고, 우리는 한국 법령·기관별 근거와 서류 점검을 합니다. 같은 도구가 국내에 없다는 것은 검색 범위 안에서 찾지 못했다는 뜻입니다. (pt/index.html 15쪽)

Q10. 정상 질문을 거절하는 일은 없나요?

A. 있습니다. 숨기지 않았습니다. 합성 사용자 40명과의 다턴 시뮬레이션에서 정상 질문 거절을 103건 → 23건으로 줄였고, 보정 후 배포본 재측정에서 자기 보호 질문을 잘못 거절한 경우가 18건(14대화) 남아 있습니다. 거절할 때도 보호 제도 대안과 1366 을 함께 붙여, 피해자가 막다른 길에 서지 않게 했습니다. (data/eval/sim_results/*/summary.md, data/eval/notice_calibration_summary.md)
