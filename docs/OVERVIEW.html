3.5 외부로 나가지 않는 것

  • 사용자 입력을 외부 LLM·외부 API 로 보내는 경로가 없습니다. 쓰는 LLM 은 GPU 서버에서 직접 띄운 Qwen 하나뿐이고, 실패해도 다른 LLM 으로 넘기지 않습니다. (docs/SPEC.md §11.7, docs/evidence/infra.md §5)
  • 런타임 코드에 있는 외부 주소는 '빠른 나가기'의 이동 대상(구글 '날씨' 검색) 하나뿐입니다.
  • GPU 서버가 기동할 때 모델 허브(HF Hub)에 파일 확인 요청을 보내던 것(경고 22회, 사용자 데이터 없음)은 커밋 6672867 에서 HF_HUB_OFFLINE=1 로 끊었습니다(gpu/start.sh). 다시 띄운 뒤(18:56:50) 새 경고는 0회입니다(20:5x 실측: 경고 수 22 그대로, 마지막 경고는 직전 프로세스, 현재 프로세스 환경에 HF_HUB_OFFLINE=1, docs/evidence/infra-2026-10-31-night.md 4절).

5. 서비스 흐름

5.1 진단 (AI 안 씀)

  1. 브라우저 → /api/diagnose {피해 유형, 상황 항목}
  2. 규칙 엔진이 84행을 하나씩 확인: 상황 조건이 맞는가 → 피해 유형이 맞는가 → 상태(시행 중/예정/없음)
  3. 세 묶음으로 나눔: 해당 제도(체크리스트) / 잔여 위험(막을 제도 없음) / 이 유형엔 해당 없음
  4. 정렬: 급한 정도 1→2→3 → 영역 순 → 번호 순, 시행 예정은 맨 뒤
  5. 화면: '지금 먼저 할 일' 최대 5건 + 나머지는 접어 둠

출처: app/engine.py, web/static/app.js

5.2 근거 질문 (이게 무슨 뜻인가요?)

  1. 질문 + 고른 제도 번호 → 운영 API 1차 가드
  2. 통지 여부·효과 시점 질문이면 AI 가 만들지 않고 지식표 원문을 그대로 보여 줌
  3. 추론 서버 2차 가드 → 지식표 행 + 공개 조문만으로 Qwen 이 답 생성
  4. 검증: 규칙 → 재순위 모델(문장마다 근거 대조) → Qwen 검증기
  5. 실패하면 한 번 다시 생성 → 그래도 실패하거나 시간이 4초 미만 남으면 원문 발췌로 대신 (전체 예산 12초)
  6. 공통 출력 가드 → 운영 API 출력 가드·인용 정리 → 화면(답 종류 배지와 함께)

출처: gpu/verify.py, gpu/server.py, app/llm.py

5.3 서류 점검

  1. 1단계(기본 점검): 브라우저 안 규칙으로만. 서버로 보내지 않음
  2. 2단계(정밀 점검): 사용자가 눌렀을 때만 서버로 → GLiNER + 정규식 → 단서 위치만 돌려줌
  3. 다시 쓰기: 원문 + 단서 → Qwen 제안 → 원문과 정렬되는지·없던 숫자·새 이름·장소가 생겼는지 검사 → 문제 있으면 규칙 치환(예: [주소 비공개])

출처: web/static/detect.js, app/main.py, gpu/server.py

5.4 가드 판정 (질문이 '다른 사람 찾기'인가?)

  1. 입력 정규화: 글자 모양 통일, 숨은 문자 제거, 인코딩된 글 풀기 등
  2. 규칙(낱말·구문) + 임베딩 의도 점수로 판정
  3. 등급 5개:
  • 본인 보호(self_protect) → 그대로 진행
  • 일반(neutral) → 그대로 진행
  • 애매함(ambiguous) → 진행하되 보호 안내 상자를 붙임
  • 제3자 탐색(third_party_locate) → 거절 + 보호 제도 대안 2~3개 + 1366·132·112
  • 다시 써 주세요(rephrase) → 초성만 쓴 글
  1. 대화 이력(최근 6턴)도 이어 붙여 다시 판정. 같은 가드를 운영 API 와 추론 서버에서 두 번 돌림

출처: app/guard.py, app/main.py, gpu/server.py (판정 규칙 원문은 공개하지 않음)

5.5 답변 검증 루프 (그림은 HTML 판 참고)

생성 → 검증 → (실패) 1회 재생성 → 검증 → (실패) 원문 발췌. 답 종류: generated(생성) · regenerated(다시 생성) · extractive(발췌) · not_found(확인되지 않음) · refused(거절).

이용 예시 시나리오 (합성, 실제 사례 아님)

가정폭력 피해로 최근 이사한 A 씨. 상대가 먼저 이혼 소송을 냈고, 초등학생 자녀는 전학 예정입니다.
  1. 공용이 아닌 자기 휴대폰, 시크릿 창으로 접속 → 안전 안내를 읽고 접음
  2. '가정폭력' 선택, '최근 이사(또는 이사 예정)', '민사·가사 소송 중이거나 예정', '가해자가 원고·채권자로 먼저 소송을 냄', '자녀가 학교에 다님' 체크
  3. '보호 제도 보기' → '지금 먼저 할 일'에서 급한 제도부터 확인. 예: 소송 중 항목을 고르면 '소송관계인 개인정보 보호조치(주소 등 비공개)'가 급한 정도 1로 나옴(data/knowledge.json J1)
  4. 통지 경고가 붙은 제도는 "상대에게 알려질 수 있다"를 확인한 뒤 신청처·서류를 봄
  5. 잔여 위험 묶음에서 막을 제도가 없는 경로를 미리 대비
  6. 답변서 초안을 '서류 점검'에 붙여 주소·학교 단서를 찾아 '[주소 비공개]' 같은 문구로 바꿈
  7. 결과를 인쇄해 1366 상담 때 가져가고, 끝나면 빠른 나가기

(각 단계의 화면 동작은 위 단계 1~8 의 코드·캡처 근거와 같습니다. 이 인물·사연은 설명을 위해 지어낸 것입니다.)

9. 한계와 다음 단계

한계 (출처: README.md 한계 절, data/eval/notice_calibration_summary.md, docs/redteam-summary.md)

  • 모든 수치는 합성 데이터에서만 나왔습니다. 실제 이용자·실제 서류로 평가하지 않았습니다.
  • 자기 보호 질문을 '다른 사람 찾기'로 잘못 거절하는 경우가 남아 있습니다(18건/14대화, 배포본 재측정). 거절 때도 보호 대안과 1366 은 붙습니다.
  • 운영 앱 측정에서 답할 수 있는 질문 15개 중 3개가 가드에 거절됐습니다(모두 같은 질문).
  • 말로 설명하기 단독 정확도는 낮습니다(다턴 시뮬레이션 유형 0.575, 상황 재현율 0.276). 그래서 사용자 확인 단계를 둡니다.
  • 생활권 단서(동네·단골 가게 등)는 찾지 못합니다(0/11). 직장 단서 재현율 0.5.
  • 소형 LLM 은 틀릴 수 있습니다(첫 생성 근거 없는 문장 3.6%). 그래서 통지·시점 질문은 생성하지 않습니다.
  • 쉬운 설명 84행 모두 사람 검수 전, 확인 수준 미확인 4행. 법령은 2026-10-31 기준 스냅샷입니다.
  • 레드팀 '대책 후' 값은 fc84eb4 기준입니다. 현재 배포본(cf8d149+6672867)으로 서비스 경로 121개를 다시 돌려 같은 3/112 = 2.7% 를 얻었습니다(2026-10-31 20:5x). 모델 단독·PAIR-lite·GLM 은 다시 돌리지 않았습니다.
  • 시연은 TLS 없이 ssh 터널로만 합니다. 추론 서버 8000 포트는 SSL-VPN 사용자에게도 닿습니다(2026-10-31 20:55 실측). 클라우드 콘솔은 쓸 수 없어 2026-11-01 부터 추론 API 가 공유 토큰을 요구합니다(토큰 없이 401). 평가 도구(tools/eval*.py)는 아직 토큰을 보내지 않습니다.
  • 동시 부하에서는 오류보다 답 품질이 먼저 떨어집니다(동시 4건 발췌 14%, 8건 50%). 1,500자 다시 쓰기는 동시 4건 이상에서 504 가 났습니다.
  • 직장 이름 단서는 정밀 점검이 자주 놓칩니다(재현율 0.5, 2026-11-01 재측정에서도 0~1건).
