## ⓐ 문제 정의 및 목표 사용자 (1쪽)

**피신해도 새 주소는 해킹이 아니라 소장·결정문·통보서로 샙니다 — 공식 경로 84개 중 16개는 막을 제도조차 없습니다.** `심사: 기획 구체성 · 기획 창의성`

| 정보보호 개념 | 이 서비스에서 |
|---|---|
| 보호 자산 | 피해자의 새 주소 — 가장 위험한 개인정보 |

### 해결하려는 문제
**피해자가 피신해도, 새 주소가 행정·소송·생활 기록을 타고 가해자에게 새어 나갑니다.**

- 위 노출 사례는 모두 해킹이 아니라 소송 서류·결정문·통보서 같은 **행정·사법 절차**에서 새었습니다.

**왜 막지 못하는가 — 구조적 원인 세 가지** (자체 법령 조사, `research/2026-10-31-정보조사.md` 1절. 조문은 `data/laws/articles.jsonl` 의 국가법령정보센터 원문 스냅샷으로 대조)
1. **신청주의**: 막는 제도는 있지만 신청해야만 작동합니다. 소송 단계 주소 비공개(민사소송법 제163조 제2항)는 법원에 미리 안내할 의무가 없습니다.
2. **피해 유형별 공백**: 주민등록·가족관계 교부 제한, 피해자보호명령은 가정폭력 피해자 전용입니다. 비가족 스토킹·교제폭력에는 없고(스토킹 피해자보호명령은 2027.4.22. 시행 예정), '교제폭력'은 법률상 정의가 없습니다.
3. **역노출**: 제한을 신청하면 그 사유가 가해자에게 서면으로 통지되는 제도가 있습니다(주민등록법 제29조 제7항 후단 등). 순서와 시점이 중요합니다.

| **차단 통제 없음** — 그중 막는 제도가 없는 경로 | **16개** (+ 시행 예정 1개, 2027-04-22) | 같은 파일 `status` |

## ⓑ 해결 방안 및 주요 기능 (2~3쪽)

**이름도 주소도 묻지 않습니다 — 상황만 고르면 새 주소의 유출 경로와 막을 제도를 급한 순서로 보여 줍니다.** AI 가 틀려도 권할 제도는 바뀌지 않습니다. `심사: 기획 구체성 · 실용 가능성`

3쪽: **가장 위험한 순간 — '신청했더니 가해자에게 통지됐다'를 신청 전에 막습니다.** 통지되는 제도는 위험을 확인해야 신청 방법이 열립니다(화면 `v5-07`·`v5-08`). `심사: 기술 완성도 · 실용 가능성`

### 서비스 개요
> 이름·주소 없이 상황만 고르거나 말로 적으면, **새 주소가 샐 수 있는 경로**와 **그 경로를 막는 제도**를 근거 조문·신청처·서류·통지 경고와 함께 **급한 순서**로 보여 주는 웹 서비스. 제출할 서류 초안 속 위치 단서도 찾아 줍니다.

**지키는 원칙** (`docs/architecture.md`, `docs/SPEC.md` §11)
- **막는 방법만** 안내합니다. 사람을 찾는 방법·조회 요건은 다루지 않고, 열람·교부 절차 조문은 검색 대상에서 뺐습니다.
- **입력을 저장하지 않습니다.** DB 가 없고, 로그에는 '메서드 경로 상태코드'만 남습니다. 표지 문자열 60회 전송 뒤 세 로그에서 0건(`docs/evidence/infra.md` §6).
- **서비스 실행 중 외부 LLM·외부 API 를 부르지 않습니다.** LLM 은 GPU 서버에 직접 띄운 Qwen3-8B 하나뿐입니다(`docs/SPEC.md` §11.7).
- **어떤 제도를 권할지는 AI 가 아니라 규칙 엔진이 정합니다.** AI 가 고른 항목은 사용자가 확인해야 제출됩니다.
- 법률정보 안내이며 법률상담이 아닙니다. 모든 화면 위쪽에 긴급 연락처 띠(112 · 1366(24시간) · 132)를, 아래쪽에 고정 도움 줄을 둡니다.
- **브라우저에 아무것도 남기지 않습니다.** 쿠키·localStorage 를 쓰지 않고, 안전 안내 열람 여부도 저장하지 않습니다(`5b7f3a7`).

### 이용 흐름
1. **안전 확인** — 방문마다 안전 안내 팝업(시크릿 창 권장, 빠른 나가기 위치), 위쪽 긴급 연락처 띠
2. **상황 입력** — 피해 유형 + 상황 체크, 또는 말로 적기 → AI 미리 선택 → 본인 확인
3. **진단 결과** — 급한 순서 체크리스트(카드는 위험 → 도움 먼저), 통지 경고 확인, 잔여 위험 대비, 결과 인쇄
4. **서류 점검** — 제출 전 초안의 위치 단서 표시와 대체 문구

**합성 예시(실제 사례 아님)**: 가정폭력으로 최근 이사, 상대가 먼저 이혼 소송을 냄, 초등학생 자녀 → '최근 이사'·'가해자가 먼저 소송을 냄'·'자녀가 학교에 다님' 체크 → '소송관계인 개인정보 보호조치(주소 등 비공개)'가 급한 정도 1로 표시(`data/knowledge.json` J1) → 통지 경고 확인 → 답변서 초안의 주소·학교를 '[주소 비공개]'로 바꿈 → 결과를 인쇄해 1366 상담에 가져감 → 빠른 나가기. (`docs/OVERVIEW.md` 6절)

## ⓒ 활용 AI 기술 및 직접 개발 범위 (4~5쪽)

4쪽: **AI 는 판단하지 않습니다 — 제도는 규칙이 정하고, AI 문장은 근거 검증을 통과해야 나가며, 피해자의 글은 우리 GPU 밖으로 나가지 않습니다.** `심사: 기획 창의성 · 기술 완성도`

흐름: 입력(저장 0) → 1단 가드(앱 규칙) → 2단 가드(GPU 임베딩 신호) → **규칙 엔진 84행이 권할 제도 결정**(AI 없음) → Qwen3-8B 설명(JSON 스키마 강제) → 문장별 근거 검증(실패 시 1회 재생성 → 원문 발췌) → 출력 가드 → 화면. 모델은 부품이고, 판단·검증 장치는 직접 만들었습니다.

**위협 모델 — 도구 자신이 새 유출 경로가 되지 않게**
| 위협 | 막는 장치 |
|---|---|
| ① 가해자가 피해자 위치를 찾으려 도구를 씀 | 2단 가드, 막는 법만 출력, 서비스에 개인 위치 데이터 0 |
| ② 가해자가 피해자 기기를 감시 | 입력 저장 0·쿠키·localStorage 0, 빠른 나가기(Esc 두 번) |
| ③ 서류 속 지시문(간접 주입) | 지시문 제거·JSON 스키마 강제·출력 가드(금지 조문·목록 밖 인용 차단) |
| ④ 진술이 외부로 반출됨 | 외부 AI 호출 0, 실행 중 모델 허브 오프라인, 표지 문자열 60회 전송 뒤 로그 0건 |

5쪽: **우리가 만든 것은 검증 장치입니다 — 그 장치가 우리 기능 하나를 출시에서 막았습니다.** `심사: 기술 완성도 · 성과`

**설계 결정 4개와 실측 근거**
1. 권고는 LLM 이 아니라 규칙이 정합니다. 결정적이고 0.005초이며, 같은 입력엔 같은 결과가 나옵니다.
2. 품질 게이트 0.90을 둡니다. '검색 답 종합'은 보류 세트 0.625로 게이트에 못 미쳐 **출시하지 않았습니다**. 1~3라운드 모두 기준 미달입니다.
3. 가드를 앱과 GPU 로 나눴습니다. GPU 가 없어도 1단 규칙 가드는 계속 동작합니다.
4. 작은 이득도 그대로 공개합니다. 재순위기 이득은 R@5 0.945 → 0.964, 1문항입니다.

**왜 이 모델인가** (선택 기준: ① 피해자 글이 서버 밖으로 나가지 않도록 자체 호스팅 ② 공공·상업 배포에 걸림이 없는 라이선스 ③ L4 1장에 네 모델이 함께 올라감 ④ 한국어)
- **Qwen3-8B-AWQ**: Apache-2.0(표시 의무·사용자 수 상한 없음). 공식 4bit 양자화본이라 vLLM 이 13,948MiB 로 다른 모델과 L4 를 나눠 씀(`docs/EVIDENCE.md` 9절). EXAONE(비상업)·Kanana-2(표시 의무)는 라이선스 때문에 뺐습니다.
- **bge-m3**: MIT, 568M. 우리 조문 보류 세트에서 Recall@5 0.945(키워드 BM25 0.800), 재순위를 붙이면 0.964(`data/eval/retrieval_baseline.md`).
- **bge-reranker-v2-m3**: Apache-2.0, 0.6B. 법률 용어 질문 1위 정확도 0.867 → 1.000. 일상 말투 질문은 1위 정확도가 0.733 → 0.633 으로 내려가는 약점이 있습니다(같은 파일).
- **GLiNER multi v2.1**: Apache-2.0. 학습 없이 '주소·학교·직장·차량·생활권' 라벨을 바로 정의하는 제로샷 모델이라 골랐습니다. 직장 4/8·생활권 0/11 은 아직 약합니다(`data/eval/results.json`).
- 한계: 대안 모델과 같은 데이터로 A/B 비교는 하지 않았습니다(마감 뒤 과제). 미세조정은 하지 않았습니다.

**런타임에 부르는 외부 AI API: 없음.** LLM 이 실패해도 다른 LLM 으로 넘기지 않고 체크박스 방식으로 계속합니다(`docs/SPEC.md` §11.7). 모델 파일은 설치 때 HuggingFace 에서 받고, 실행 중에는 `HF_HUB_OFFLINE=1` 로 허브 접속을 끊었습니다(커밋 `6672867`).

## ⓖ 기대 효과 및 확장 가능성 (9~10쪽)

9쪽: **몰라서·늦어서·순서를 틀려서 새는 주소 — 피해자는 놓친 제도를, 상담 현장은 첫 상담 점검표를, 정책은 막을 수 없는 16개 경로를 얻습니다.** `심사: 성과 및 실용 가능성`

변화 이론: 상황을 고름 → 유출 경로·제도·통지 위험을 앎 → 소송·이사·신고 **전에** 비공개 신청 → 서류로 새는 일 감소(**검증 예정**).

**아직 증명 안 된 것 → 다음 게이트**: 사람 검수 0/84 → 84/84 · 레드팀 3.6%(3/84) → 확대 세트로 재측정 · 공개 전 TLS·인증·접근 범위·속도 제한. 실제 이용자 효과는 미검증(합성 평가만).

10쪽: **해외도 한 번에 다 막지 못합니다 — 그래서 경로별 진단, 다음 1년은 사람 검수와 상담 현장 시범으로 증명하겠습니다.** `심사: 기획 구체성(실행·확장 계획)`

### 실제 적용 가능성
- **이미 배포·실측된 구성**입니다. GPU 1장(L4)에 모델 4종이 올라가고(19,648/23,034MiB, `docs/evidence/deploy-2026-11-01.md`), 진단은 CPU 에서 0.005초입니다(`docs/evidence/infra.md`).
- **용량과 비용(실측 기반)**: 품질을 지키는 동시 2에서 L4 1장이 시간당 약 200세션을 처리합니다. 현재 구성을 NCP 공공기관용 정가로 셈하면 약 140만 원/월(약 1,943원/시간, GPU 서버 83%)이고, 꽉 찰 때 세션당 약 9.7원, 세션당 약 2.2만 토큰입니다. 늘 꽉 차지는 않으므로 실제 세션당 비용은 이용량으로 정해집니다(`docs/COST_LATENCY.md` §3-3).
- **GPU 가 없어도 핵심은 돕니다.** 진단은 규칙 엔진, 검색은 BM25 로 대체, LLM 기능은 숨긴 채 체크박스 방식으로 계속(`README.md`). 저비용 배포 선택지가 있습니다.
- **대회 서버는 2026-11-01 13:00 에 삭제됩니다.** 그 뒤의 재현 경로는 두 가지입니다. ① `README.md` 실행 절(NVIDIA GPU 필요, 모델은 미리 내려받아 두고 실행 중에는 오프라인) ② GPU 없는 모드: 모의 GPU 서버 `tools/mock_gpu.py` 로 화면 전체를 띄움(`docs/LOCAL_DEV.md`). 삭제 전에 GPU 서버의 패키지·모델 판본을 읽기 전용으로 옮겨 두었습니다(`docs/evidence/repro-2026-11-01.md`, `gpu/uv.lock`). 평가 스크립트와 합성 데이터는 저장소에 있습니다.
- 법적 경계를 설계에 반영했습니다: 무료·일반 법률정보 안내(변호사법 제109조 검토), 인공지능기본법 제31조 제2항(생성형 AI 결과물 표시, 2026.1.22. 시행)에 따라 AI 문장에 'AI 생성' 표시, 입력 비저장·위치 권한 요청 없음(`research/…` 7절).

### 한계 (숨기지 않음)
- **범위**: 행정·사법 기록으로 주소가 새는 84개 경로만 다루며, 조사하지 못한 항목 25개가 남아 있습니다(`research/…` 11절). 직장·생활권·디지털 기기 경로는 단서 탐지만 하고 막는 제도는 안내하지 못합니다. 법률정보 안내이며 법률상담이 아닙니다.
- **사람 검수 0/84**: 쉬운 말 설명은 모두 AI 초안이고 화면에 'AI 생성·검수 전'으로 표시합니다. 지식표 미확인 4행도 남아 있습니다.
- **합성 평가**: 모든 수치는 지어낸 데이터로 잰 값입니다. 실제 피해자·실제 서류로는 재지 않았습니다.
- **레드팀**: 현재 배포본에서 검색·답 경로 고정 공격 84건 중 가드가 거절하지 못한 것 3건(3.6%, 95% 구간 1.2–10.0%). 남은 원인은 한국어 자모 변형 1, 다국어 혼용 2입니다. 2026-10-31 회차(서비스 경로 전체 112건)는 5건(4.5%)이었고, 그중 본인 보호 문형 오인 1건은 가드 낱말 보강(S017)으로 막았습니다. 상황 정리 항목 오염 1건(intake 경로)은 다시 재지 않았습니다. 통과한 응답은 노출 허용 조문이나 '찾지 못함' 고정문이었고, 조회 방법이 나온 응답은 0건입니다(한국어 정규식 자동 검출 기준, 재현율 미측정). 대책 전후 비교는 같은 세트라 개선으로 주장하지 않고, 재검토는 사람이 아니라 Claude 가 했습니다. 위치 찾기에 대한 적응형 자동 공격은 공격자 모델이 역할을 거부해 하지 못했습니다(`docs/EVIDENCE.md` 0절, `docs/redteam-summary.md`).
- **출시하지 않은 기능(부정적 결과)**: 검색 결과를 LLM 이 종합해 답하는 '검색 답 종합'을 실험했으나, 1라운드(개발 세트)·2라운드(보류 세트)·3라운드(보류 세트, 지시문·검증기 수정) 모두 품질 게이트(답한 것 중 정답률 0.90 이상 등)를 넘지 못했습니다(엄격 정답률 2라운드 0.625, 3라운드 0.421, `docs/EVIDENCE.md` 0-15). 3라운드의 GPU 지시문·검증기 변경은 기존 회귀 시험도 통과하지 못했습니다. 그래서 배포하지 않았습니다. 위 '근거 답 45문항 0.956'(`/api/answer`)과는 다른 기능입니다.

### 공개 전에 반드시 할 일
- TLS, 모든 기능의 속도 제한, 인증·운영 정책(시연은 ssh 터널 전용). 동시 처리 상한(실측상 동시 2 이하 권장)과 프로세스 자동 재시작도 아직 없습니다.

- 위 레드팀 통과 3건(현재 배포본) 막기와 회귀 시험 등록, 자기 보호 질문 오거절 18건/14대화 줄이기, 생활권 단서 탐지(0/11)·직장 단서(재현율 0.5) 보강.

| ④ 기술 안전 도구·클리닉 | 기기·계정 점검, 지원기관 연결 | 미국 Cornell CETA 클리닉, 영국 Bright Sky | 행정·사법 경로를 진단하는 도구는 조사 범위에서 찾지 못함(부재 증명은 아님) |

- 어느 나라도 한 번에 다 막지 못합니다. 그래서 **경로별 진단**이 제도가 생겨도 필요합니다.
- 한국과 가장 닮은 일본(신청주의 + 개별 조치)은 대상에 스토킹을 넣고, 한 번의 결정을 선거·등기·법인 경로로 재사용하게 했습니다.

### 정책 제안 (해외 선례가 있는 것)
1. **보호 대상 확대**: 주민등록·가족관계 교부 제한을 스토킹·교제폭력 피해자까지(일본 지원조치는 스토커 포함).

3. **비어 있는 경로 입법**: 선거인명부 익명 등재(영국), 부동산 등기 공시용 주소(일본 2024), 법인 대표자 주소 비표시(일본 2022·2024). 보안 예보의 '잔여 위험' 16개 경로가 그 목록입니다.
