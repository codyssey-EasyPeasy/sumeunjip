## 1. 요약

### 지금 아는 것
- **응답 시간 [실측]**
  - 진단(`/api/diagnose`)은 0.005초다(규칙 엔진, CPU만 쓴다).
  - 자유 서술 정리(`/api/intake`)는 약 1.5~1.8초다.
  - 검색(`/api/search`)은 약 1초다. 그중 대부분이 재순위(약 1.2초)다.
  - 카드 질문 답변(`/api/answer`)은 p50 2.6~3.0초, p95 약 10~11.6초다. 최대 12.67초로, 12초 예산을 넘은 사례가 있다.
  - 문장 바꾸기(`/api/rewrite`)는 글자 수에 비례한다. 1,500자에서 39~41초가 걸린다(시간 제한 60초).
  - vLLM 냉기동은 약 161초다.
- **처리량 [실측]**: vLLM 단일 요청 생성 속도는 p50 35.7 tok/s, p90 45.8 tok/s 다. 동시 3~4건에서 합계 약 115~120 tok/s 로 올라간다.
- **비용 [공개 정가]**: 지금 구성을 NCP 공공기관용 정가로 셈하면 **약 140만 원/월**(약 1,943원/시간)이다. 이 중 GPU 서버가 83%다.
- **세션당 자원 [추정]**: 보통 세션은 LLM 호출 약 7.5회, 토큰 약 1.2만, GPU 점유 약 22초를 쓴다.

### 모르는 것
- 해커톤 주최 측이 실제로 청구받는 금액과 계약 조건, 서버의 실제 스펙 코드, 디스크 종류, VPN 계정 수(**미확인**). 인프라 비용은 주최 측이 부담한다.
- **동시 사용자 수에 따른 지연**. 부하 시험을 한 적이 없다. 그래서 "GPU 1장당 몇 명"은 추정뿐이다.
- 큰 표본의 p95/p99, 사용자 여정 전체 시간, 느린 망에서의 첫 화면 시간, GPU 모델 서버(bge-m3·재순위·GLiNER)의 기동 시간.
- 개발 단계에서 쓴 외부 LLM(DeepSeek 초안, GLM 시뮬레이터·레드팀)의 비용. 오너 게이트웨이를 거쳤고 원가 근거가 없다(**미확인**).
- 지시문에 적힌 "48 tok/s" 의 출처. 저장소 안에서 찾지 못했다(**미확인**). 이 문서는 실측 p50 35.7 / p90 45.8 tok/s 를 쓴다.

### 2-2. 사용자 여정 시간 추정 [추정, 위 실측 중앙값의 합]

사람이 읽고 입력하는 시간은 뺐다. 서버를 기다리는 시간만 셌다.

| 단계 | 호출 | 대기(중앙값) | 대기(나쁜 경우) |
|---|---|---|---|
| 첫 화면 | 정적 파일 88.9KB (gzip 없음) | 미확인 (사내망 1초 미만 추정) | Slow 3G 에서 미확인 |
| 자유 서술 → 확인 | intake 1~2회 | 1.7s × 1.6 ≈ 2.7s | 2.4s × 3 ≈ 7s |
| 진단 결과 | diagnose | 0.005~0.06s | 0.12s |
| 카드 질문 | answer 1회 | 2.6~3.9s | 11~15s |
| (선택) 관련 조항 찾기 | search | 1.0s | 1.5s, 첫 호출이면 8s |
| (선택) 서류 문장 바꾸기 | rewrite 500자 | 약 15~23s | 1,500자면 39~41s |

- **기본 여정**(서술 → 진단 → 질문 1회)의 서버 대기 합계는 **중앙값 약 5~7초, 나쁜 경우 약 20초**다.
- 앱이 스트리밍을 쓰지 않는다. 그래서 사용자가 체감하는 시간은 첫 토큰 시간이 아니라 응답 전체 시간이다.
- 이 표는 **혼자 쓸 때** 값이다. 동시 사용자가 늘면 어떻게 되는지는 모른다(§2-3 #4).

### 3-4. 용량 추정

- L4 1장이 처리할 수 있는 세션은 **시간당 약 95(보수) ~ 250(중간) ~ 600(상한)** 이다. 실측으로 받친 것은 세션당 점유 시간(약 22초)뿐이다.
- **실제 한계는 처리량보다 12초 답변 예산일 가능성이 크다.** generated 답의 p90 이 이미 11.3초다(v3). 동시 처리로 스트림 하나가 15~20%만 느려져도 답이 생성되지 않고 발췌로 바뀐다. 즉 부하는 오류가 아니라 **품질 저하**로 먼저 나타난다 [추정].
- 처리량 실측(동시 3~4에서 약 120 tok/s 포화)으로 보면 동시 사용자 한계는 4~5 근처로 추정한다(미검증).
- 그 밖의 상한도 있다.
  - rewrite 동시 2건 [코드]
  - GPU 서버 vCPU 4개
  - KV 캐시. 0.6 × 22.5GiB ≈ 13.6GiB 에서 가중치를 빼면 약 6GiB, answer 기준 동시 약 20건으로 추정한다. `llm.log` 로 확인 가능하지만 **미확인**이다.
