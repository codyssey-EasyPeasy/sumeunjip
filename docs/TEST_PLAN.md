## 공통 규칙

- **배포본은 읽기 전용으로만 쓴다.** 재기동, 배포, 서비스 중단을 하지 않는다. 배포본에 대한 접근은 `ssh -F ~/.config/hackathon-ssh/config` 터널로만 하고, 터널은 끝나면 PID 로 닫는다. 쓰는 포트는 18000(GPU), 18001(vLLM), 18080(앱)이다.
- 입력은 모두 합성 데이터다. 공격 문구는 저장소에 쓰지 않고 실행할 때 만든다.
- `web/` 은 frontend 브랜치 작업자의 영역이라 고치지 않는다. 화면에서 결함을 찾으면 수정 제안으로만 넘긴다. (2026-11-01: frontend 브랜치는 PR #2 로 main 에 병합됐다. 원칙은 같다.)
- 배포본 GPU 를 함께 쓰는 실측 시험(⚡ 표시)은 차례대로 하나씩 돌린다. 부하가 큰 시험은 밤 시간에 끝내고, 시연 리허설과 겹치지 않게 한다.
- **P0 에서 결함이 나와도 이 계획 안에서는 고쳐서 배포하지 않는다.** 결함마다 "시연 전에 고쳐 배포할지, 한계로 말할지"를 오너가 정한다. 결정 시점은 11-01 09:00 을 제안한다.
- "중단" 칸은 시험 중에 서비스가 멈추는지를 뜻한다. "오너" 칸은 오너가 손으로 해야 하거나 오너의 결정이 필요한지를 뜻한다.
